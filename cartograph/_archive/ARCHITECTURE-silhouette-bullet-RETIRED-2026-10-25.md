- **The neighborhood silhouette — one SSOT (`src/cartograph/boundary.js`).** The disc is a **circle, always** (`[[project_neighborhood_disc]]`): center + nominal radius + a 256-pt polygon hugging it, plus two radial feather bands — `fade {inner,outer}` (face-fills) and the wider `streetFade {inner,outer}` (streets trail past faces). All of it loads from **one artifact**, `cartograph/data/<id>/neighborhood_boundary.json` (v2 schema, v1 fallbacks) — *to move or reshape the neighborhood, edit that JSON and re-bake; no code changes anywhere.* `boundary.js` is the **single source of truth every consumer reads** and it does a lot: membership tests `pointInBoundary` / `faceInBoundary` / `streetInBoundary` (bake-time stencil-cull + runtime clip, ~17 call-sites), the radial-fade constants (`FADE_INNER/OUTER`, `STREET_FADE_INNER/OUTER` — face + street shaders), the bake bbox, the raw `boundaryPolygon` outline, and two polyline clippers — `clipPolylineToBoundary` (exact 256-gon) and `clipPolylineToRadius` (cheap exact-circle, used by `MapLayers` to stop debug centerlines at the *visible* feathered edge). The disc is the **Intake-stage** artifact (the protoslab container's geography + boundary; `ORIENTATION §3` (Extent, Intake), `SKELETON.md §1`). The aerial layer reads the same disc — `AerialTiles.jsx` covers it with a low-res base + an on-demand hi-res **focus** layer (attention-driven, tile-capped, orphaned-fetch-aborting). Banked future payoff: clip-at-bake retires the runtime stencil entirely (wall-move ledger). *(2026-07-03 — this is where the disc gets **written**, by the Extent tool: a fresh scene's boundary is defined by eye and committed to this artifact; see §8 "The Extent tool & the Pour." The pour then uses it as a **data wall** — `pipeline.js` clips derived features to the circle so an overshooting boundary arterial can't skew the content bounds. **⭐ 2026-07-20 — the disc RENDERS, it does not DECIDE.** Membership is `((polygon − exclusions) ∪ activate) − hide`: the operator's **inclusion polygon** is the test, **exclusion loops** (`nb.exclusions`, persisted alongside) + per-building `activate`/`hide` are corrections, and the disc is only the **fallback** when a scene carries no polygon — `NEIGHBORHOOD-INPUTS §5.2`. ⛔ *This parenthetical previously stated the 2026-07-14 **excluder model** — "the disc … IS the membership boundary, every building inside is IN" — which was RETRACTED; it made subtraction the only gesture and silently cost 147 Księży Młyn buildings.
